# 調査: 汎用 Router 化と価格リスク（実測記録）

> 2026-09-30。「たくさんある Provider に対する汎用 Router」への拡張を検討する過程で、
> (1) 現状の価格の扱い、(2) pathUSD / USDC のレート乖離、(3) 額変化の防御を実測した。
> **実装変更は行っていない**（調査のみ）。

## 1. 現状の価格の扱い（ソースで確認）

| 要素 | 実際 | 所在 |
|---|---|---|
| 上流の価格・資産・宛先 | **動的**。402 を実際に読む | `src/adapters/outbound/x402.ts:84-102` |
| 上流の **URL** | **設定固定** | `config.ts` の `upstreams[routeId]` |
| route の存在 | **設定固定**（未知は `unknown_route`） | `orchestrator.ts:285` |
| **受信額** | **設定の固定値**（`route.source.amount`） | `orchestrator.ts:310` |

**したがって現状は「上流が言った額をそのまま受信額にする」ことをしていない。**
受信・送信は**独立した固定値**であり、レートも比率も参照していない。
ハッカソンのデモで受信 1234 zETH / 送信 10000 USDC だったのは、
レート換算の結果ではなく**そう設定していただけ**である。

「価格を調査する」機能は**既に動いている**（Provider A の `10000` は実測値）。
固定されているのは価格ではなく **route 定義**であり、汎用化に必要なのは
「任意 URL の受け入れ」であって「価格調査の追加」ではない。

## 2. pathUSD / USDC のレート乖離（実測）

| 項目 | 値 | 出所 |
|---|---|---|
| 現在の乖離 | **0.0174%**（pathUSD 1.0 / USDC 0.999826） | CoinGecko simple/price |
| pathUSD 24h 変動 | +0.4985% | 同 |
| **歴史的最大乖離** | **下方 17.6%**（atl 0.824）/ 上方 7.2%（ath 1.072） | CoinGecko coins/pathusd |
| 24h 出来高 | **$17,591** | 同 |
| 時価総額 | **0.0**（算出されていない） | 同 |
| 取引ペア | **2 本、いずれも Tempo Stablecoin DEX** | 同 |
| pathUSD の decimals | **6**（USDC と同じ） | `cast call` on chain 42431 |

### 2.1 結論: 手数料（spread）でリスクを吸収する案は成立しない

平常時 0.017% に対し、**過去に 17.6% 乖離している**。spread で最悪ケースを覆うなら:

- spread 0.1% → 平常時は足りるが**乖離時に即赤字**
- spread 18% → 安全だが**誰も使わない料率**

**保険料が商品価格を超える**ため、「手数料でリスクをカバーする」が破綻する。

### 2.2 レートが「取得できる」が「信頼して額を決められない」

- 取引ペアが **2 本で同一 DEX** → 単一取引所依存。停止すればレートが取れない
- 出来高 **$17K** の板は**操作可能**。Router がそのレートで額を決めるなら、
  攻撃者は先に板を動かして有利な換算を作れる
- 時価総額が算出されていない

**レートの取得可能性と、レートを信頼して金銭を決定できることは別要件**であり、後者を満たさない。

### 2.3 さらに: 現在扱っているのは testnet の pathUSD

`rpc.moderato.tempo.xyz`（chain 42431）は **testnet**。
CoinGecko の価格は mainnet の pathUSD なので、
**現行実装が扱う資産の価格ではない**。上記の乖離データが mainnet 移行後に
そのまま当てはまる保証もない。

### 2.4 owner 判断

**価格変動リスクの扱いは mainnet 対応時に検討する**（2026-09-30）。
testnet 資産の実測から spread を決めても、mainnet では前提が変わるため
根拠のない数字を固定することになる。

## 3. 「額変化を検知していない」懸念 → **穴は無かった**

`selectOffer`（`orchestrator.ts:184-190`）は scheme / network / asset / payTo を照合し、
**`amount` を見ていない**。ここから「上流が価格を上げても同じ offer として通り、
差額を Router が無言で負担する」という懸念を持ったが、**誤りだった**。

### 3.1 実際には二重に守られている

| 層 | 仕組み | 所在 |
|---|---|---|
| core | `quoteFingerprint` が offer 全体の `stableJson` の SHA-256（**`amount` を含む**） | `intent.ts:132-134`, `orchestrator.ts:353` |
| core | 送金直前・settle 直前に `stableJson` **完全一致**を再照合 | `orchestrator.ts:669-672`（`:428`, `:572` から呼ばれる） |
| adapter | 送金前に上流を読み直し、不一致なら `not_sent` | `x402.ts` / `mpp.ts` |

`selectOffer` が額を見ないのは「**どの offer を選ぶか**」の条件であり、
選んだ後の**同一性保証は fingerprint と再照合が担っている**。役割分担であって穴ではない。

### 3.2 既存テストが固定している

| テスト | 内容 |
|---|---|
| `tests/wire/x402-outbound.test.ts:114` | 送金直前に `amount` が変われば **署名も送信もしない**（`destination_offer_changed`、signer 呼び出し 0） |
| 同 `:128` | 承認と外れた額（`amount: "1"`）では signer に到達しない |
| `tests/wire/mpp-outbound.test.ts:119` | MPP でも同様 |
| `tests/unit/lifecycle.test.ts:1021` | **core 層**: 受信成立後に上流が `1200` に変わったら送金せず `quote_changed` で終了（`payCalls` 0） |

### 3.3 sabotage で裏付け

`readAndMatchDestination` の照合を `return offers.length > 0` に置き換えると、
`tests/unit/lifecycle.test.ts` の **2 件が失敗**する
（「上流の提示が変わったら送金しない」「承認済み selectedOffer は adapter 側の変更で書き換わらない」）。
**テストは実際にこの性質を守っている。**

→ **修正不要。** 懸念は解消した。

## 4. 汎用 Router 化に向けて残る論点（未着手）

実測を踏まえると、汎用化の障害は価格ではなく**宛先の認可**である。

現在の `routeId` は 3 つの役割を兼ねている:

1. **予算の境界** — 設定に無い route は quote できない。任意 URL を許すと
   「予算内なら任意の宛先に払える」ことになる。**額は制限できても宛先は制限できない**
2. **承認の対象** — 人間が承認する subject に `resource.url` が含まれる。
   URL が動的なら、承認時に「どこに払うか」の判断が人間に移る
3. **`routeBinding`** — 受信 offer が `routeId|method|path` に束縛され、
   承認した経路以外で使い回せない

**汎用化とは、設定が担っていた信頼の役割を別の仕組みに移すこと**である。
候補（オリジン allowlist / 宛先ごとの人間承認 / 承認済み宛先の学習）は
いずれも「何が宛先を認可するか」の置き方が異なる。**別スライスとして設計する。**

なお**同一資産でも汎用 Router は成立する**: 変換しているのは
**プロトコル**（x402 ⇄ MPP ⇄ SubEtha）であって資産ではない。
「同じ USDC を x402 で受け取って MPP で払う」は価格リスクなしに成立し、
手数料も「受信額 = 上流価格 + fee」で取れる（レートを知る必要がない）。

## 5. **§2 の数字を訂正する — 乖離は実在しなかった**

> 2026-10-01。§2 で「歴史的最大乖離 17.6%」「24時間で 0.90〜1.02（約12%）」と報告したが、
> **これらは設計根拠として使えない**。測定の仕方が誤っていた。

### 5.1 何を間違えたか

**CoinGecko の導出 USD 値を実勢価格として扱った。** 実際の DEX ペア価格は par 近傍である。

自分で再取得して確認した値（2026-10-01）:

| 指標 | 値 |
|---|---|
| **pathUSD/USDC.e（実ペア）** | **0.9999003**（−0.010%） |
| **USDT0/pathUSD（実ペア）** | **0.9998977**（−0.010%） |
| **板のスプレッド（両ペア）** | **0.60%** |
| CoinGecko 導出 USD 値 | 取得時刻により 0.9936 / 0.9919 / **1.0** と振れる |

**実ペアは導出値より約 80 倍 par に近い。** そして **乖離（0.01%）がスプレッド（0.60%）より
二桁小さい**——つまり観測された「乖離」は**板の薄さによる見せかけのノイズ**であり、
経済的な depeg シグナルではない。

出来高は 2 ペア合計で約 **$10.9K**（実測 8,401 + 2,553）。
CoinGecko は USDT0 ペアに **`is_anomaly`** を立てたことがある。

### 5.2 「ATL 0.8244」の正体

CoinGecko の ATL（2026-08-22）は数値としては実在するが、
**薄い板に対する導出 USD 系列の記録**であり、**実際に 17.6% の depeg が起きた証拠ではない**。
§2.1 で「平常時 0.017% に対し過去 17.6% 乖離」と対比したのは、
**異なる種類の数字を並べた誤り**だった。

### 5.3 Tempo mainnet は稼働しており、pathUSD は法定通貨担保だった

§2.3 で「現在扱っているのは testnet の pathUSD」と書いたのは正しいが、
**「mainnet のデータが当てはまる保証がない」という留保の向きが逆だった。**

自分で確認（2026-10-01）:

| 項目 | 実測 |
|---|---|
| **Tempo mainnet** | **稼働中**（chainId `0x1079` = 4217、ブロック 42,028,107） |
| **pathUSD（mainnet）** | `symbol()` = `pathUSD`、`decimals` = 6、**供給量 59,903,679.59** |

調査報告より（私は未確認）: 発行者は **Bridge（Stripe の規制対象発行体）**、
USDC.e を 1:1 で預けて mint、準備金は短期国債等。
Tempo mainnet には **USDC.e（供給量 9,218万＝pathUSD の 1.54 倍）** と **USDT0** も存在する。

**つまり pathUSD は faucet トークンではなく、実在する法定通貨担保ステーブルコインである。**
testnet の `PathUSD`（**大文字 P、シンボルが異なる**）は供給量が mainnet の **3 億倍**で、
そちらが faucet トークン。私が触っていたのは testnet 側だった。

### 5.4 市場は実質的に単一通貨（USD）だった

Coinbase x402 Bazaar の**全数調査**（19,375 リソース、2026-10-01）:

| 分類 | 割合 |
|---|---|
| **USD ステーブルのみ** | **94.43%**（18,296） |
| USD + 非USD 混在 | 4.13%（801） |
| **非USD のみ** | **0.01%（2 件）** |

さらに非USD の裾は見かけより薄い:
- 非USD を受け付ける 45 ホストは**実質 13 事業者**に収束
- 非USD 受付リソースの **99.9%（716/717）が説明文で USD 建てを表示**
- **EURC の 72%（185/257）は USD と 1:1 で値付け**（実際の ~1.08 レートを無視）

`pay.sh` のスキーマは**資産・チェーンの欄を持たず** `min_price_usd` / `max_price_usd` のみ。
**構造的に USD 建て**である。

→ **FX リスクは存在しない。** Router が扱うのは常に USD ペッグ同士であり、
実勢の乖離は **1bp**（スプレッド 60bp に埋もれる水準）。

### 5.5 本当の変換面は FX ではなく「ステーブル間スリッページ」

Tempo mainnet が複数ステーブル（pathUSD / USDC.e / USDT0 / OUSD）を持ち、
`mppx` の `currency` は**任意のトークンアドレス**（`0x20c0…0000` は per-chain の既定値にすぎない）。

→ 現実的な課題は **Tempo DEX 上のステーブル間スリッページ**であり、
通貨間 FX ではない。実測スプレッド **0.60%** がその規模感。

### 5.6 §2.4 の owner 判断は維持されるが、理由が変わる

「価格変動リスクは mainnet 対応時に検討」という判断自体は妥当だが、
**理由は「乖離が大きいから」ではなく「実勢では乖離が小さく、
今は単一通貨経路で足りるから」**である。

### 5.7 教訓

**導出された集計値を実勢価格として扱ってはならない。**
薄い板では、スプレッド・出来高・異常フラグを同時に見ないと、
集計値のノイズを経済シグナルと誤認する。
今回は**スプレッド（0.60%）が主張した乖離（0.01%）より二桁大きい**ことを
最初に確認すべきだった。
